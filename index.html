02 / How I work

Start with the problem.
Stay close to the evidence.

The model matters. So do the assumptions, the evaluation, and the decisions around it.

01.

Understand the setting.

Start with the physical problem and the people who need an answer. Define what useful performance actually means.

02.

Question the average.

Look at the conditions behind a result. Separate familiar examples from the situations a system has not seen.

03.

Test the whole system.

Consider signal processing, model behavior, latency, power, and the workflow that turns a prediction into an action.

04.

Make the limits clear.

Explain what the evidence supports, what still needs testing, and when a system should ask for another look.

03 / A little about me

Make it work.
Know when
it doesn’t.

A useful place to start, in research and in practice.

I’m interested in the space between a promising research result and a system someone can actually rely on.

My work brings together AI, sensing, and systems thinking. CrossSense explores that through a practical question: how should a sensing system respond when the input is noisy, the context changes, or the deployment environment is less forgiving than the experiment?

I also care about the work around the model: clear requirements, sensible data structures, testing, and explanations that help people make informed decisions.

I like starting in plain English and then going technical. A useful explanation should make the reasoning clearer, not hide it behind terminology.
